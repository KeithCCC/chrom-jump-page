# TabNest 1.1.2 — 導入・更新手順

新しいタブを開くたびに「ブックマークバー」直下のサイトとフォルダを表示します。サブフォルダ内のサイトは、そのフォルダをクリックして開きます。

## 既存版の更新（設定を引き継ぐ場合）

1. `chrome://extensions/` で現在のTabNestの「詳細」を開き、読み込み元フォルダを確認します。拡張機能は削除しないでください。
2. そのフォルダを別の場所にコピーしてバックアップします。
3. GitHubから取得したソースを一時フォルダに展開します。
4. 解凍した中身を、現在読み込んでいる `manifest.json` があるフォルダへ上書きします。
5. `chrome://extensions/` でTabNestの再読み込みボタンを押します。
6. 新しいタブを開いて確認します。

Chromeの詳細画面に表示される読み込み元を使ってください。同じ場所・同じ拡張機能のまま更新すると、ピン留め順序・テーマ・表示密度を引き継げます。別フォルダから新規登録すると別の拡張機能IDになり、設定を引き継げない場合があります。

## 新規導入

1. このリポジトリをクローンするか、GitHubの「Code」からZIPをダウンロードして展開します。
2. 展開先の直下に `manifest.json` があることを確認します。
3. Chromeで `chrome://extensions/` を開き、「デベロッパーモード」をオンにします。
4. 「パッケージ化されていない拡張機能を読み込む」で、**manifest.jsonが直接入っているフォルダ**を選びます。
5. `Ctrl + T` で新しいタブを開きます。確認が出た場合はTabNestを使用する選択肢を選びます。

TabMarkなど他の新規タブ拡張機能が有効な場合は、そちらを無効にしてTabNestを有効にします。通常の利用にビルドやnpmは不要です。

ZIPを展開した場合は、その中の `manifest.json` が直接入っているフォルダを選びます。

```text
展開先/
  manifest.json
  newtab.html
  app.js
  styles.css
  icons/
    icon16.png
    icon32.png
    icon48.png
    icon128.png
  README.md
  VALIDATION.md
  package.json
  package-lock.json
  tests/
    regression.cjs
```

## 複数選択・移動・削除・編集

1. 各ブックマーク・フォルダのカード右上にある「選択」をチェックします。選択用の欄は常に表示されるため、スクロールした先でもその場で複数選択できます。ピン留め一覧や検索結果でも使用できます。
2. 移動は、選択したカードを左の目的フォルダへドラッグするか、目的フォルダ横の「ここへ移動」を押します。フォルダ名のクリックは従来どおりフォルダ移動です。
3. 削除は「選択項目を削除」を押し、件数と名前を確認します。「キャンセル」なら削除しません。削除はChrome本体に反映されます。フォルダを削除する場合は中身も対象です。
4. 1件だけ選んで「編集」を押すと、ブックマークの名前・URL、またはフォルダ名を変更できます。
5. 「表示中を選択」は、その時点で読み込んで表示しているカードを選択します。大量の一覧では「さらに表示」を押した後に再度選択してください。ピン留めと一覧の同じブックマークは1件として数えます。
6. 「選択を解除」、または各カードのチェックを外して通常操作へ戻ります。選択中の操作バーはスクロールしても画面上部に残ります。完了メッセージは「閉じる」で消せます。

選択はフォルダや検索を切り替えても保持し、選択件数は画面に表示します。ページ再読み込み・新規タブでは選択をリセットします。ドラッグは同じTabNestタブ内で行ってください。別タブからのドラッグは受け付けません。

ブックマークバーなどの標準フォルダや管理対象の項目は選択できません。フォルダを自分自身やその配下へ移動する操作もできません。親フォルダとその中の項目を同時に選んだ場合は、親フォルダ単位でまとめて処理し、重複操作を避けます。

移動はブックマークIDを保つため、ピン留め順序も維持します。削除したブックマークはピン留めからも取り除きます。一部が失敗した場合は結果を表示し、失敗した項目の選択を残します。

## 変更内容と従来機能

- 初回導入後も、その後も、新規タブ・ページ再読み込みのたびにブックマークバー直下を表示します。
- 左側のフォルダ選択を強調し、パンくずと見出しにも表示場所を示します。
- 開いたタブ内でのフォルダ移動は維持します。ブックマーク再読み込みボタンや変更イベントでは現在のフォルダにとどまります。
- ピン留めは「ピン留めしたサイト」または「すべてのブックマーク」から従来どおり利用できます。起動時はバーの一覧を表示します。
- ピン留め・解除、ドラッグでの並べ替え、サイト名・URLの全体検索、追加、テーマ、表示密度を維持しています。
- バーが空の場合は空の状態を表示し、他フォルダのサイトを代わりに一覧表示しません。
- 初回に最大8件を自動ピン留めする従来機能も維持しています（バー直下にサイトがなければ全体から選択）。初期表示対象とは別の処理です。

## フォルダ判定

Chrome 134以降の `folderType: "bookmarks-bar"` を優先します。該当フォルダが複数ある場合はID `"1"`、なければAPIが返す最初の該当フォルダを選びます。folderTypeがない古い環境では、ルート直下のID `"1"` を参照します。翻訳されたフォルダ名には依存しません。

複数のバーは統合せず、各フォルダを左側から選択できます。バーが見つからない場合は説明を表示します。

参照：[Chrome Bookmarks API](https://developer.chrome.com/docs/extensions/reference/api/bookmarks)

## 導入後の動作確認

1. 新規タブで、バー直下のサイトとフォルダだけが表示されることを確認します。
2. サブフォルダへ移動した後、別の新規タブを開きます。新しい方はバー直下から表示されます。
3. 「ピン留めしたサイト」で既存のピン留めと並び順を確認します。
4. 他フォルダのサイトを検索し、検索を消すと元のフォルダへ戻ることを確認します。
5. Chromeを終了・再起動して新規タブを開き、表示先とピン留めの保存を確認します。

Chromeの起動ページ設定や、前回の通常タブを復元する設定は変更しません。

## データと権限

bookmarks（閲覧・追加）、storage（表示設定）、favicon（Chrome内のアイコン）を使用します。権限の追加はありません。導入時に既存ブックマークを削除・移動・名前変更しません。ピン留め解除でも元のブックマークは消えません。

設定は chrome.storage.local に保存し、別PCへ自動同期しません。Chrome Web Storeには公開していません。

## 開発者向けテスト

Node.js 22.20以降の対応環境で、展開先から `npm ci`、`npm test` を実行すると28項目の回帰テストを実行できます。テスト用依存パッケージは拡張機能の実行には不要です。確認範囲は VALIDATION.md を参照してください。
